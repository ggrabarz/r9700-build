    Engines¶

    On gfx1201 the engine is not a detail — it is worth 2.06× at the same concurrency, and MTP another 1.61×. The production stack is the Radiance family, not upstream vLLM and not Strata. Strata is the capacity tool for models that do not fit.

    1. What actually runs, in order of fitness¶

    Engine Status on R9700 What it is for
    vLLM-Radiance (stilldeadcode/vllm-radiance) The production engine. vLLM 0.30.0 fork, gfx1201-only, TP=2-qualified, ships 25 hand-written RDNA4 kernels (libr4d). Dense models that fit: Qwen3.8-27B FP8, two engines × TP=2 per quad.
    Standalone Radiance (C++/HIP) The throughput ceiling. ar_oneshot_4rank / r4d_ar_oneshot_8rank_exact, --tp-wire exact. TP4 monolith and TP8 GLM-5.3-Flash; 236 → 1,192 tok/s.
    Strata (Niko1221/Strata) Validated on R9700 (gfx1201) 2026-09-30. C++/ggml, layer split + expert streaming, MTP, PLE table on SSD. Models larger than VRAM: Flash-Next, GLM-5.3-Flash at low bit-width, DeepSeek packs.
    llama.cpp (ROCm) Works; layer split is not TP. Capacity/experimentation, not serving: plateaus at 56 tok/s.
    Upstream vLLM (ROCm) Works at TP=2/4 with NCCL_PROTO=Simple; attention falls back to Triton. Baseline only; Radiance is faster on every measured point.
    SGLang No gfx1201 image upstream. FlagOS fork has TP=4 correctness on 4× R9700, no performance numbers. Not a production option.
    TensorRT-LLM / Marlin / BitBLAS / FA3 / FlashMLA / DeepGEMM Do not exist for gfx1201. —

    2. The measurement that decides the engine¶

    Puget Systems, 2 × R9700, bare metal, Qwen3.6-27B FP8, TP=2, same model and quant across rows:

    Stack c=1 c=8 Verdict
    llama.cpp Q4_K_M, layer split 23.40 56.00 plateaus — no continuous batching
    stock vLLM FP8, TP=2 15.88 156.21 baseline
    vLLM-Radiance, TP=2 32.00 198.78 2.06× stock at c=8
    vLLM-Radiance, TP=2 + MTP 62.75 320.23 another 1.61×

    Two facts follow:

    1. Layer split loses on throughput even though it has less traffic and fewer sync points. Its stages are a serial dependency; vLLM's batching fills each card. Use layer split for capacity, never for a model that fits.
    2. MTP is free throughput — validation is exact and output is bit-identical. Turn it on.

    The production topology is DP × TP=2, i.e. n_engines = cards / 2. Two independent engines per four-card box, each with Qwen's own FP8 checkpoint, FP8 KV cache, the in-checkpoint MTP draft head, ≤8 concurrent requests, ≤262,144 tokens.

    3. vLLM-Radiance: the production recipe¶

    3.1 Host and container¶

    There is no host ROCm. The reference machine runs Ubuntu Server 26.04.1 with the in-tree amdgpu driver and nothing else for the GPUs; ROCm arrives inside the serving container. "No rocminfo on Ubuntu — that's expected."

    Floor Value
    Host kernel must carry gfx1201 amdgpu support
    Container ROCm 7.14 / 7.2.4 — the Radiance ports pin it. Not ROCm 10.
    Why not ROCm 10 KFD ABI mismatch; PyTorch 2.13+ hangs on gfx1201; LLVM mnemonic changes break libr4d and AITER wave32 assembly
    Container plumbing privileged: true, shm_size: "32g", ipc: host, /dev/kfd, /dev/dri, groups video + render, HIP_FORCE_DEV_KERNARG=1, VLLM_TARGET_DEVICE=rocm

    You cannot benchmark the card from the host — no rocminfo, no host rocm-smi that reflects the container. Bring-up is "does the container serve tokens".

    3.2 Environment variables that matter¶

    Variable Value Why
    NCCL_PROTO=Simple always, any RCCL path gfx1201 has no RCCL tuning index → index 0 → TP≥2 deadlocks (ROCm/rccl PR #2166)
    GPU_MAX_HW_QUEUES=1 always fixes the gfx1201 slow-dispatch state (seen on 6/8 boots); 139 → 210 tok/s
    HSA_ENABLE_IPC_MODE_LEGACY=0 vLLM-ROCm ≥0.21 avoids hipIpcGetMemHandle: invalid argument; do not re-add NCCL_P2P_DISABLE / RCCL_NET=Socket
    VLLM_ROCM_USE_AITER_UNIFIED_ATTENTION=1 Radiance image the one AITER family that serves traffic on gfx1201
    VLLM_ROCM_USE_AITER_MHA/_MLA/_MOE/_LINEAR/_FP8BMM/_FP4BMM/_RMSNORM=0 Radiance image the CK/ASM families are CDNA-only
    VLLM_ROCM_USE_AITER_LINEAR=1 only after validating output can silently emit NaN at TP≥2 when per-rank K is not a multiple of 1024 (vllm#28649)
    amdgpu.ras_enable=0 kernel cmdline 40 → 97 tok/s in one measured build

    3.3 Flags¶

    • --tensor-parallel-size 2 for the dense 27B. TP=2 is forced by memory, not preference: 27.8 GB of FP8 weights + 262 K of FP8 KV does not fit one 32 GB card.
    • MTP on (--spec / the in-checkpoint draft head). +61 % at c=8.
    • Never --enforce-eager — it roughly halves decode and removes graph capture, which is where much of the gfx1201 gain lives.
    • --tp-wire exact for standalone Radiance TP4. wht6 at 4 ranks is a tiered int8 + Hadamard wire, not 6-bit, and it is lossy above 128 KiB messages for ~2 % prefill.
    • --pipeline-windows 2 for Strata on 2+ stages: moves the draft layer to the first card; 2-card decode 103 → 125 tok/s, +22 % at 4 cards.
    • hipBLASLt tuning table must match the shipped hipBLASLt version — 1.84× on a 2048-token prompt when it matches, ~0 % when it does not. Version-lock the container.

    3.4 What libr4d provides¶

    25 hand-written RDNA4 kernels: paged attention, fused GDN prefill scan, P2P one-shot all-reduce, skinny bf16 GEMM, W4A8. Plus FP8 KV cache (2.12 M tokens on 2 × 32 GiB, 5.6× BF16) and a Mamba-align prefix cache that fixes the hybrid-attention cache problem upstream vLLM still has.

    Radiance ships 2-rank and 3-rank one-shot kernels; 4-rank was added by brainchillz/r9700-tp4-allreduce (PR jdrews/vllm-mxfp4#2), and 8-rank by r4d_ar_oneshot_8rank_exact.

    4. Standalone Radiance: the TP4 / TP8 ceiling¶

    The measured reference is B14, brainchillz's TR PRO 9955WX + 122 GB DDR5, four cards on CPU-direct Gen5 x16 at 211 W:

    Concurrency 1 2 4 8 16
    tok/s 236 371 591 890 1,192

    11.27 ms/step. That is ~3× the same box on llama.cpp + speculative decode (65–75 tok/s) and ~45 % ahead of 2 × TP=2.

    A second, independent Gen4 box (EPYC 7R13, 256 GB DDR4-3200) reproduces ~7.8–8.2k prefill and 170–244 tok/s TG from 100 k to 250 k context with the tuned flags (B18).

    The TP8 path exists and is measured on one model: GLM-5.3-Flash, 3,958 tok/s prefill @6 k, 166 single-stream, 426 over 8, 506 @8 streams = 53.25 tok/s/GPU, +29.6 % over the quad's 41.08. The all-reduce cost is 27.3 µs per 8-rank one-shot, 46 collectives/token = 1.26 ms = 20.9 % of every token. It does not shrink with bandwidth.

    5. Strata: the capacity engine¶

    Strata is a C++ engine on parts of llama.cpp/ggml. Its multi-GPU model is layer split, not tensor parallel — there is no --tp 4. It does MoE expert streaming natively: hot experts in VRAM, the rest in pinned host RAM, misses computed on the CPU, the model file on SSD with a PLE (prompt lookup expert) table.

    Measured on one R9700 (Coder IQ1_M): 982 tok/s at 4 K prompt, 45.5 tok/s decode; 1,402 tok/s at 16 K; 29.7 GiB peak VRAM; 12,288 expert slots (23.4 GiB); ~26 GB host resident.

    Three switches that moved the needle:

    Switch Effect
    STRATA_HIP_WMMA (FP16 QSA attention on matrix cores) 7.2–7.5× the portable kernel; 4 K prompt 1,784 → 2,427 tok/s
    v_perm_b32 replacing a byte shuffle decode +15 % (46.0 → 53.0 tok/s)
    MoE router without the serial FP64 sum 39 → 9–12 µs/call; decode 62.4 → 70.0 tok/s
    Exact long-prompt QSA scorer (STRATA_SCORES_THREAD=1, default on gfx12) 3.6× at 131 K, 4.0× at 240 K

    Split scaling vs one card: 16 K prompt +36 / +45 / +53 % at 2 / 3 / 4 cards; 32 K +18 / +21 / +29 %; 64 K +4 / +12 / +17 %.

    Strata is not the engine for a model that fits. Its layer split plateaus far below vLLM's continuous batching. It is the engine for a working set that exceeds VRAM.

    6. The other engines, honestly¶

    • SGLang upstream: rocm.Dockerfile builds only gfx942 / gfx950 / gfx1250. No gfx1201 image. The FlagOS fork (flagos-ai/sglang-plugin-FL PR #157) loads and serves Qwen3.6-35B-A3B at TP=4 on 4× R9700 with FlagTree + FlagCX and passes validation — correctness only, no perf. Not a production option.
    • llama.cpp: layer split often beats tensor split for MoE (97 vs 67 tok/s on PCIe 5.0 x16), and its MTP aggregates invert after c4 on a four-card box (45.0 → 90.8 at c4 → 73.3 at c8). Useful for capacity and for proving a box; not for serving.
    • Aphrodite: inherits vLLM + ROCm; no independent R9700 result.
    • Paiton: 1–2 cards only.
    • Saber / LemonSeed: new single/dual-card engines; Saber's own README refuses TP=4, so its 6,645 tok/s headline cannot be attached to a quad.

    7. Engine decision table¶

    If the model… Engine Topology
    fits in 4 × 32 GB (Qwen3.8-27B FP8) vLLM-Radiance 2 × TP=2, MTP on, FP8 KV
    fits in 4 × 32 GB and needs max single-stream standalone Radiance TP4, ar_oneshot_4rank, --tp-wire exact
    is an MoE that fits only at low bit-width standalone Radiance (MXFP4/Quark) TP2/TP4
    exceeds VRAM (Flash-Next at Q5+, DeepSeek packs) Strata layer split, PLE table in RAM
    is GLM-5.3-Flash on 8 cards standalone Radiance TP=8 only; TP=4 impossible (MLA latent replicated)

    The one-line rule: many small TP groups on the Radiance stack; layer split only when the model does not fit; never upstream vLLM when Radiance is available.
